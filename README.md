# Sona

複数の音声・動画ファイルをまとめて文字起こしし、結果を 1 つのファイルに統合して保存できる macOS アプリです。文字起こしの方式は Whisper・ReazonSpeech・Apple（macOS 標準）から選べます。
文字起こしと動画の変換はすべてこの Mac の中で行い、音声や結果を外部へ送信しません。

- SwiftUI のネイティブ macOS アプリ（Apple Silicon / arm64 専用、App Sandbox 有効）
- 認識エンジン（方式）:
  - **Whisper**: [whisper.cpp](https://github.com/ggml-org/whisper.cpp) v1.9.5（Metal による GPU 処理）
  - **ReazonSpeech**: 日本語専用の [reazonspeech-k2-v2](https://huggingface.co/reazon-research/reazonspeech-k2-v2) を [sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx) v1.13.8 で実行
  - **Apple**: macOS 標準の音声認識（Speech フレームワークの SpeechAnalyzer）
- 動画: 音声を取り出して MP3 に変換してから文字起こし（MP3 エンコードに [LAME](https://lame.sourceforge.io/) 4.0）
- **ライブ文字起こし**: 画面で再生中の動画やオンライン会議の音声（選んだウィンドウ・システム全体）とマイクを取り込み、Whisper でリアルタイムに文字起こし（後述）
- 表示言語: 日本語・英語（macOS の優先言語から自動選択、設定で切り替え可）
- 書体・文字の大きさ、背景（色・画像）とライト／ダークを設定で変更可
- 既定の方式・モデル: Whisper の Large v3 Turbo（量子化 Q5_0、574 MB）／文字起こしの初期言語: 日本語

## インストール

1. [Releases](https://github.com/TKMS981/Sona/releases/latest) から、使うエディションの DMG をダウンロードします（下記「エディション」）。
   - AI の機能を使う: `Sona-Vantage-<バージョン>.dmg`（アプリ名は「Sona」）
   - AI の機能を使わない: `Sona-Air-<バージョン>.dmg`（アプリ名は「Sona Air」）
   - 1.2.0 は旧形式の `Sona-1.2.0.dmg`（開発版）、1.1.1 までは旧名の `WhisperBatch-<バージョン>.dmg` です。[リリースの一覧](https://github.com/TKMS981/Sona/releases)から選べます。
2. DMG を開き、「Sona」（または「Sona Air」）を「Applications」フォルダへドラッグします。Sona Vantage は、これまでの Sona・Whisper Batch と同じアプリとして設定とモデルを引き継ぎます。Sona Air は別のアプリ（Bundle ID が別）なので、Vantage と並べて入れられ、設定とモデルは別に持ちます。旧名の「Whisper Batch」を使っていた場合は、後述「名称の変更（Whisper Batch → Sona）」も参照してください。
3. 初回は macOS が「開けません」「検証できません」と表示します（Developer ID 署名と公証をしていないため）。
   1. ダイアログを「完了」で閉じます。
   2. 「システム設定」→「プライバシーとセキュリティ」を開き、下の方にある「Sona」の「このまま開く」を押します。
   3. もう一度アプリを開き、確認ダイアログで「開く」を押します。

   ターミナルを使う場合は `xattr -dr com.apple.quarantine "/Applications/Sona.app"`（Air は `"/Applications/Sona Air.app"`）でも開けるようになります。

ダウンロードしたファイルは、リリースに添付した `.sha256` の値と `shasum -a 256 <DMG のファイル名>` の結果が一致するかで確認できます。

## 名称の変更（Whisper Batch → Sona）

このアプリは「Whisper Batch」から「**Sona**」に名前を変えました。アプリ名・メニュー・ウインドウのタイトル・DMG とビルドしたアプリのファイル名（`Sona.app`、`Sona-<バージョン>.dmg`）が新しい名前になります。

これまでの設定・取得済みのモデル・背景画像を引き継ぐため、次のものは**変えていません**。

| 変えていないもの | 値 | 理由 |
| --- | --- | --- |
| Bundle ID | `com.example.WhisperBatch` | サンドボックスのコンテナ（モデル・設定・背景画像の置き場所）と、macOS の許可の管理がこの値に結び付いているため |
| アプリのデータのフォルダ | コンテナ内の `Application Support/WhisperBatch/`（`Models/`・`Background/`） | 取得済みのモデル（数百 MB〜）を取り直さずに使うため |
| 設定の保存先 | Bundle ID と同じ名前の設定（UserDefaults） | 設定をそのまま引き継ぐため |

- 一時ファイルの置き場所だけは変えました（`<一時フォルダ>/Sona-Live/`・`Sona-Conversions/`、どちらもプロセスごとのサブフォルダ。下記「一時ファイル」）。旧版（Whisper Batch 1.1.1 まで）は起動・終了時に `WhisperBatch-Conversions/` をフォルダごと消すため、同じコンテナを使う旧版と同時に動かしても Sona の処理中のファイルが消されないようにしています。一時ファイルだけなので移行は不要です。旧版の `WhisperBatch-Conversions/` と、開発中の版が使っていた `WhisperBatchLive/` は、Sona からは消しません（旧版が使用中かもしれないため）。
- 保存先を変えていないので、データの移行処理は不要です。Sona を起動すると、これまでのモデルと設定がそのまま使われる設計です（旧アプリからの置き換えを実機で試したわけではありません）。
- 古い `/Applications/Whisper Batch.app` は、Sona を入れたら削除してください。同じ Bundle ID のアプリが 2 つあると、macOS がどちらを開くかが分かりにくくなります。
- macOS の「プライバシーとセキュリティ」の一覧には「Sona」と表示されます。アドホック署名のビルドは作り直すたびに別のアプリとして扱われることがあり、その場合は画面収録やマイクの許可を求め直されます（名前の変更とは関係なく、以前から同じです）。
- ソース内部の名前（Swift のモジュール名 `WhisperBatchCore` / `WhisperBatchEngine`、`Sources/WhisperBatch/` などのフォルダ名、テスト用の環境変数 `WHISPER_BATCH_*`）は変えていません。
- GitHub のリポジトリ名は 2.0.0 で `whisper-batch` から `Sona` に変えました（`https://github.com/TKMS981/Sona`）。古い URL は GitHub が新しい URL へ転送します。手元の複製は `git remote set-url origin https://github.com/TKMS981/Sona.git` で新しい URL に変えられます。
- ライセンス表記（MIT の著作権表示、同梱ライブラリのライセンス）はそのままです。「Whisper」「whisper.cpp」は、認識に使うモデルとライブラリの名前としてそのまま使います。

## 動作環境と、この環境での制約

| 項目 | 内容 |
| --- | --- |
| 対象 OS | macOS 27 以降（`LSMinimumSystemVersion` / デプロイメントターゲットとも 27.0） |
| CPU | Apple Silicon のみ（arm64 でビルド。Intel / Rosetta は対象外） |
| ビルド環境（確認済み） | macOS 27.0.1、Command Line Tools（Swift 6.4、macOS 27.0 SDK）、Apple M5 |

開発した Mac には **Xcode がなく、Command Line Tools だけ**でした。そのため次のようにしています。

- Xcode プロジェクトではなく **Swift Package** で構成し、`scripts/build-app.sh` で `.app` バンドルを組み立てます。
- 署名の既定は **アドホック署名**（ローカル実行用）です。他の Mac に配布するには Developer ID 署名と公証（notarization）が必要で、そのための環境変数を用意しています（後述「Developer ID 署名と公証」）。
- macOS 27 SDK では SwiftUI の `@State` が Xcode 同梱のマクロとして解決され、Command Line Tools ではビルドできません。`State` を型エイリアス `ViewState` 経由で使っています（`Sources/WhisperBatch/Views/ViewState.swift`）。
- swift-testing のマクロプラグインが自動で読み込まれないため、`scripts/test.sh` が `-load-plugin-library` を付けて実行します。
- String Catalog（`.xcstrings`）は Xcode の `xcstringstool` がないとコンパイルできないため、表示文字列は従来の `.strings` 形式で管理しています（後述）。
- Bundle ID は仮の `com.example.WhisperBatch` です（`App/Info.plist`）。公開・配布する場合は自分のドメインに変更してください。

## ビルドと実行

```sh
./scripts/build-app.sh          # リリースビルド → build/Sona.app
open "build/Sona.app"
```

ビルド時に次のものをネットワークから取得し、どちらも内容をハッシュで検証します。

| 取得するもの | 取得元 | 検証 |
| --- | --- | --- |
| whisper.cpp の XCFramework（約 66 MB） | GitHub（ggml-org/whisper.cpp のリリース b5454） | `Package.swift` のチェックサム（SwiftPM が検証） |
| llama.cpp の XCFramework（約 65 MB、Vantage だけが使う） | GitHub（ggml-org/llama.cpp のリリース b11976） | `Package.swift` のチェックサム（SwiftPM が検証） |
| LAME 4.0 のソース | SourceForge（公式配布物 lame-4.0.tar.gz） | アーカイブの SHA-256（`scripts/fetch-lame.sh`）と、展開したファイルの一覧（`ThirdParty/LAME/CLAME.sha256`） |

LAME は `scripts/fetch-lame.sh` が取得し、必要なソースとヘッダーだけを `ThirdParty/LAME/Sources/CLAME/` に展開します（このフォルダは Git の追跡対象外）。配布物に含まれる `configure` などのスクリプトは実行せず、macOS 用の設定ヘッダー `ThirdParty/LAME/config.h` を使って SwiftPM でコンパイルします。`build-app.sh` と `test.sh` は自動で取得します。`swift build` を直接使う場合は先に `./scripts/fetch-lame.sh` を実行してください。

- 取得するのは固定の URL・バージョン（4.0）のアーカイブだけで、展開前にアーカイブの SHA-256 を確かめます。展開先に置くのは libmp3lame のソースとヘッダー、`include/lame.h`、`mpglib/` と `vector/` のヘッダー（コンパイルはしない）、ライセンス文、`config.h` のコピーです（計 48 ファイル）。
- 展開したファイルは、**展開済みのときも毎回**、Git で管理している一覧 `ThirdParty/LAME/CLAME.sha256`（各ファイルの SHA-256）と照合します。ファイルの変更・欠落・追加・シンボリックリンクがあればビルドを止めます（Finder が作る `.DS_Store` だけは数えません）。止まった場合は `rm -rf ThirdParty/LAME/Sources/CLAME` の後にやり直すと、公式の配布物から取得し直します。以前の版のスクリプトが作った目印のファイル（`.lame-4.0`）は使わずに消します。
- 一覧はスクリプトが書き換えることはありません。LAME を更新するときや `ThirdParty/LAME/config.h` を変えたときは、`./scripts/fetch-lame.sh --print-manifest`（アーカイブの SHA-256 を確かめてから組み立てた内容の一覧を標準出力に出す）の結果で一覧を更新し、差分を確認してからコミットしてください。

生成物の `build/Sona.app`（Vantage）には、`whisper.framework`・`llama.framework`・`libLAME.dylib`・`libsherpa-onnx-c-api.dylib`（どれも arm64）、日本語・英語の文字列、ライセンス表記が入ります。`WB_EDITION=air` で作る `build/Sona Air.app` には `llama.framework` を入れません。whisper.framework と llama.framework はそれぞれ ggml を内蔵しているため、同じ Swift のモジュールからは読み込みません（llama は `SonaLLM` だけが `internal import` します）。

ビルドスクリプトは署名の前に、実行ファイルと `libLAME.dylib` からデバッグ用の参照情報を取り除きます（`strip -S -x`）。この情報にはソースやオブジェクトファイルの絶対パス（ビルドした Mac のユーザー名を含む）が入るためです。クラッシュ時のシンボル解決に使う dSYM は `.build/` にだけ残り、アプリには含めません。`.build/` の中身はローカルパスを含むので公開・配布しないでください。

### 配布用 DMG の作成

```sh
./scripts/make-dmg.sh               # アプリをビルド → build/Sona-<バージョン>.dmg と .sha256
./scripts/make-dmg.sh --no-build    # build/Sona.app をそのまま DMG にする
```

- バージョンは `App/Info.plist` の `CFBundleShortVersionString` から取ります。
- DMG の作成には [dmgbuild](https://github.com/dmgbuild/dmgbuild)（PyPI、バージョン固定）を使います。初回に `.build/dmg-venv` へ取得します。Finder を操作しないので、オートメーションの許可は不要です。
- ウィンドウの背景画像は `scripts/make-dmg-background.swift` で生成し、アイコンの配置などは `scripts/dmg-settings.py` で設定します。
- DMG にする前に、アプリ内のファイルにこの Mac のホームディレクトリのパスが含まれていないかを調べ、含まれていれば中止します。

### Developer ID 署名と公証

環境変数を指定すると、Developer ID 署名と公証を行います（指定しなければアドホック署名のまま）。

```sh
# 公証用の認証情報をキーチェーンに保存しておく（最初の 1 回。App 用パスワードを入力）
xcrun notarytool store-credentials sona --apple-id <Apple ID> --team-id <Team ID>

# 署名・公証した DMG を作る
WB_SIGN_IDENTITY="Developer ID Application: <名前> (<Team ID>)" \
WB_NOTARY_PROFILE=sona \
./scripts/make-dmg.sh
```

| 環境変数 | 使うスクリプト | 内容 |
| --- | --- | --- |
| `WB_SIGN_IDENTITY` | `build-app.sh`、`make-dmg.sh` | 署名に使う証明書の名前（`security find-identity -v -p codesigning` で表示されるもの、またはその SHA-1）。指定すると、同梱ライブラリとアプリをこの証明書で署名し、**Hardened Runtime**（`--options runtime`）と署名時刻（`--timestamp`）を付けます。DMG にも署名します |
| `WB_NOTARY_PROFILE` | `make-dmg.sh` | `notarytool` のキーチェーンプロファイル名。指定すると、アプリと DMG をそれぞれ公証し（`notarytool submit --wait`）、チケットを添付（`stapler staple`）してから SHA-256 を計算します。`WB_SIGN_IDENTITY` が必要です |
| `WB_DISABLE_LIBRARY_VALIDATION=1` | `build-app.sh`、`make-dmg.sh` | **通常の配布では使いません。** Developer ID 署名のときに `com.apple.security.cs.disable-library-validation` を付けます（下記「Hardened Runtime での動作」参照）。既定では付けません。`WB_SIGN_IDENTITY` なしで指定するとエラーにします。署名後に、この例外が指定したときだけ付いていることを確かめます。`make-dmg.sh` は、例外の付いたアプリを、同じコマンドでこの変数を明示していなければ DMG にしません |

- 証明書やプロファイルが見つからない場合は、ビルドを始める前に中止します。公証が受け付けられなかった場合は、`notarytool log` の内容を表示して中止します。
- 同梱ライブラリ（`whisper.framework`・`libLAME.dylib`・`libsherpa-onnx-c-api.dylib`）を先に、アプリ本体を最後に、同じ証明書で署名します。
- この Mac には Developer ID の証明書がないため、**署名・公証の経路は実際には試していません**（確認できたのは、指定なしでのアドホック署名と、証明書・プロファイルが見つからないとき・`WB_DISABLE_LIBRARY_VALIDATION` の指定が正しくないときに中止すること）。アドホック署名のビルドが成功しても、Developer ID 署名・公証・他の Mac の Gatekeeper で通ることの確認にはなりません。初めて使うときは、できた DMG を別の Mac で開いて確認してください。

## テスト

```sh
./scripts/test.sh                        # ロジックのテスト（キュー、状態遷移、出力形式、チャンク境界、表示文字列など）
```

実際の音声・動画とモデルを使う結合テストは、環境変数を指定したときだけ実行されます。テスト素材はリポジトリに含めず、スクリプトで生成します。

```sh
./scripts/make-test-audio.sh /tmp/wb-audio          # say と ffmpeg（Homebrew）でテスト用の音声・動画を作成
WHISPER_BATCH_TEST_AUDIO_DIR=/tmp/wb-audio \
WHISPER_BATCH_TEST_MODEL=/path/to/ggml-large-v3-turbo-q5_0.bin \
WHISPER_BATCH_TEST_DOWNLOAD_DIR=/tmp/wb-models \
./scripts/test.sh
```

- 安全性のテスト: ライブ文字起こし・変換の一時フォルダがプロセスごとに分かれ、動いている別のプロセス（強制終了させる perl の子プロセスで試す）のファイルを消さず、終了したプロセスの残りだけを消すこと。モデルのダウンロードで、受信量がカタログの大きさを超えたら受信を止めること、エラーの応答・大きさの不一致・SHA-256 の不一致・中止のどの場合も検証前のファイルが残らないこと、中止と失敗を区別すること（`huggingface.co` の代わりに応答する試験用の仕組みを使い、通信はしない）、再開時の受信量の数え方、読み込み前の照合で同じ大きさの書き換えを検出すること。LAME の展開済みのソースの変更・欠落・追加・シンボリックリンク・`config.h` のコピーの変更でビルドが止まること（作業用のコピーで試す）
- 表示文字列のテスト: 日英のキーが一致しているか、書式指定（`%@`・`%ld` など）が両言語で一致しているか、ソースで使っているキーがすべて定義されているか、英語に日本語が混ざっていないか
- 動画のテスト: 対応形式の変換（出力が MP3 として読めて長さが一致し、元ファイルが変わらないこと）、非対応形式・音声のない動画・存在しないファイルのエラー、キャンセル時に書きかけの MP3 が残らないこと、動画 → MP3 → Whisper での文字起こし
- 容量不足のテストは、小さいボリュームを用意して `WB_SMALL_VOLUME` にそのパスを指定したときだけ実行されます
- ライブ文字起こしの結合テスト（`Tests/WhisperBatchEngineTests/LiveIntegrationTests.swift`）は、`WHISPER_BATCH_TEST_MODEL` に加えて、`WHISPER_BATCH_TEST_LIVE_SPEECH`（実時間で流し込む音声。話の切れ目を含むもの）、`WHISPER_BATCH_TEST_LIVE_WINDOW`（音声を再生しているウィンドウのタイトル。画面の音声の取り込みを試す。テストを実行するターミナルに画面収録の許可が必要）、`WHISPER_BATCH_TEST_LIVE_CLOSING_WINDOW`（数秒後に閉じるウィンドウのタイトル）、`WHISPER_BATCH_TEST_LIVE_EXPECT`（結果に含まれるはずの語、カンマ区切り）を指定したときだけ実行されます。音声を再生するアプリは `open` で起動してください（ターミナルから直接起動すると、macOS がその音をターミナルの音として扱います）
- ライブ文字起こしの品質評価（`Tests/WhisperBatchEngineTests/LiveQualityEvaluation.swift`）は、`WHISPER_BATCH_TEST_MODEL`、`WHISPER_BATCH_TEST_EVAL_SPEECH`（音声）、`WHISPER_BATCH_TEST_EVAL_REFERENCE`（正解の文章）を指定したときだけ実行されます。音量の変更（`_EVAL_GAIN_DB`）、合成の伴奏（`_EVAL_MUSIC_DB`）、語彙のヒント（`_EVAL_HINT`）、比較用の設定（`_EVAL_VARIANT`）などの指定はファイルの先頭に書いています
- ReazonSpeech と Apple のテスト（`Tests/WhisperBatchEngineTests/OtherEngineTests.swift`）は、`WHISPER_BATCH_TEST_SPEECH`（日本語の音声）、`WHISPER_BATCH_TEST_LONG_SPEECH`（1 分以上の日本語の音声、任意）、`WHISPER_BATCH_TEST_REAZON_DIR`（ReazonSpeech のファイルを置いたフォルダ）、`WHISPER_BATCH_TEST_APPLE_SPEECH`（英語の音声）を指定したときだけ実行されます

- 確からしさの結合テスト（`Tests/WhisperBatchEngineTests/FeatureIntegrationTests.swift`）は、`WHISPER_BATCH_TEST_AUDIO_DIR` と `WHISPER_BATCH_TEST_MODEL`（Whisper）、`WHISPER_BATCH_TEST_REAZON_DIR`（ReazonSpeech k2 v2）、`WHISPER_BATCH_TEST_APPLE_CONFIDENCE`（英語の音声。Apple）を指定したときだけ実行されます

## 使い方

1. 音声・動画ファイルを追加します。
   - **ウィンドウ内のどこにでも**ドラッグ＆ドロップ（キュー、結果表示、設定パネル、下部の操作バーのどこでも可。複数ファイル・フォルダ可）
   - 「ファイルを追加…」（⌘O）、Finder でアプリのアイコンにドロップ、または「このアプリケーションで開く」
2. モデルが未取得なら「ダウンロード…」を押し、確認ダイアログで取得元・サイズ・保存先を確認してからダウンロードします。
3. 文字起こしの言語を選び、「文字起こしを開始」（⌘R）を押します。キューの上から順に処理し、「キャンセル」（⌘.）で中止できます。
4. キューの項目を選ぶと結果を確認できます（タイムスタンプ表示、コピー、⌘F で検索）。
5. 保存します。
   - **統合して保存…**（⇧⌘S）: 含める結果と順番を決めて、1 つのテキストファイルにまとめます。
   - **個別に書き出す…**: 完了した結果をフォルダへそれぞれ書き出します（TXT / SRT / VTT）。
   - 各結果の「このファイルを書き出す」: 1 件だけ書き出します（TXT / SRT / VTT）。
   - 動画の項目では「**音声を MP3 で保存…**」で、動画の音声を MP3 として好きな場所に保存できます（このときだけ MP3 を残します）。
6. 保存し終えたら、キューの下部にある「**完了 N件を消去**」で完了した項目をまとめて片付けられます（完了した項目があるときだけ表示。「⋯」メニューの「完了した項目をすべて削除」と同じ）。文字起こし結果も消えるので、先に保存してください。

### キューの扱い

- **状態表示**: 音声は「待機中 → 文字起こし中 → 完了」、動画は「変換待ち → MP3 に変換中 → 文字起こし中 → 完了」と表示し、それぞれ進捗（%）を出します。失敗・キャンセル済みも項目ごとに表示します。
- **重複**: 同じファイル（シンボリックリンクや `..` を解決した同じパス）は追加しません。スキップしたことを表示し、既にある項目を選択します。
- **対象外のファイル**: 拡張子が音声・動画でないファイル（.txt など）は追加せず、理由を表示します。読み込めない形式は追加直後の確認で失敗として表示します。
- **失敗**: 1 件が失敗しても残りの処理は続けます。
- **削除・再試行**: 選択項目の削除（⌫）、待機中の一括削除、処理中以外の一括削除、失敗・キャンセルした項目の再試行。
- キューと結果はアプリを終了すると消えます。処理中・変換中に終了しようとすると確認します。

### モデルの管理（設定の「AI モデル」）

- 取得・保持・削除・切り替え: モデルごとに、用途（日本語向け・英語向け・多言語・翻訳専用・軽量・高性能）、配布元、パラメーター数、量子化、ファイルの大きさ、動かすのに必要なメモリの目安、ライセンス（リンク）、取得元のリポジトリとリビジョン（リンク）、動作の確認の有無を表示します。
- 取得は、確認画面（取得元・リビジョン・ライセンス・大きさ・保存先）で同意したときだけ行います。取得元は `huggingface.co` に限り（既存の接続先の確認をそのまま使う）、リビジョンを固定した URL から取得し、SHA-256 が一致したときだけ使えるようにします。読み込む前にも照合します。
- 進み具合の表示・中止・再開: 中止すると再開用のデータを残し、「再開」で途中から取得します（検証前のファイルは残しません）。「最初から取得」も選べます。
- 更新: モデルの一覧（リビジョンと SHA-256）はアプリに固定してあり、自動では更新しません。将来の版で一覧のリビジョンが変わり、以前のリビジョンのファイルが残っている場合は「更新があります」と表示し、更新するまでは以前のリビジョンを使います（以前のリビジョンの SHA-256 も一覧に残します）。
- 削除は確認してから行います。読み込み中のモデルは解放してから削除します。
- 保存先は文字起こしのモデルと同じフォルダの `llm/<モデル>/` です（`~/Library/Containers/<Bundle ID>/Data/Library/Application Support/WhisperBatch/Models/llm/`）。
- モデルがなくても、文字起こし・編集・書き出しなどは従来どおり使えます。

### モデルの選び方

| 選び方 | 内容 |
| --- | --- |
| 自動（既定） | 文字起こしの言語と用途に合わせて、取得済みのモデルから選ぶ（日本語: 日本語向け → 多言語 → 英語向け、英語: 英語向け → 多言語 → 日本語向け、その他: 多言語 → 英語向け → 日本語向け。同じなら高性能のもの）。取得済みのモデルがなければ Apple Intelligence（使える場合）、それもなければ案内 |
| 言語共通 | 1 つのモデル（または Apple Intelligence）を、どの言語・用途にも使う（翻訳専用のモデルは選べない） |
| 用途別 | 誤認識の修正・文章の整形・要約（重要な発言を含む）・翻訳ごとに、自動・Apple Intelligence・特定のモデルを選ぶ |

- 必要なモデルがないときは、取得はせずに「設定の『AI モデル』で取得してください（候補: …）」と案内し、設定を開くボタンを出します。
- 翻訳は、翻訳専用のモデル（PLaMo）を優先します。翻訳専用のモデルはほかの用途には使いません。Apple Intelligence は翻訳には使いません。
- 推論のときに読み込むモデルは 1 つだけです。別のモデルを使うときは前のモデルを解放してから読み込みます（設定の「解放」でいつでも解放できます。アプリの終了時にも解放します）。物理メモリの 60%（32GB の Mac で約 19GB）を超えそうなモデルは読み込みません。

### AI の処理の決まり

- 誤認識の修正と文章の整形は別の機能です（編集画面の「AI 誤認識修正」「AI 文章整形」）。誤認識の修正は、確からしさが低い語を手がかりに、聞き間違い・同音異義語の誤りだけを直します。文章の整形は、句読点を補い、フィラーと言い直しを除くだけで、語は変えません。
- 反映のしかたは「候補を確かめてから反映」（既定。差分を見て、候補ごとに採用・却下）と「自動で反映」から選べます。どちらも原文は残り、区間ごと・今回の分・全体を原文に戻せます。
- AI の候補は次の検査（`RewriteGuard`）を通ったものだけを使い、通らなかったものは理由とともに一覧に示して、原文のまま残します。
  - 数字・日付・金額（全角・半角を区別しない、単位付きの漢数字を含む）、カタカナの語、大文字を含む英字の語（文頭を除く）、敬称の前の語（人名）、英語の人名・地名・組織名が、原文と同じだけ残っていること。原文にないものが現れないこと。
  - 文章の整形は、原文の文字（英語などは語）の並びを削るだけで作れること（言い換え・追加をしていないこと）。
  - 誤認識の修正は、変えた文字が全体の 3 割以下であること。
- 依頼の文でも、人名・地名・製品名・数字・日付・金額を推測で変えない、原文にない情報を足さない、判断できない文は出力しない（原文のまま）ことを指示しています。
- 長い文字起こしは、モデルの文脈の長さに合わせて区切り、1 つずつ順に処理します（同時に複数を処理しません）。
- 重要な発言は AI に番号を選ばせ、文は文字起こしのものをそのまま使います。翻訳は原文を変えず、訳文を別に表示します（Markdown で書き出すと入ります）。
- Apple Intelligence は FoundationModels の端末内のモデル（`SystemLanguageModel.default`）だけを使います。macOS 27 の FoundationModels には Private Cloud Compute 上のサーバーのモデル（`PrivateCloudComputeLanguageModel`）もありますが、このアプリはその型を参照しません（テストでソースを確かめています）。

### この Mac での確認（2026-11、Apple M5 / 32GB / macOS 27.2）

採用した 14 モデルをすべて取得して SHA-256 を照合し、llama.cpp b11976 で読み込んで、合成した短い文字起こし（日本語 5 文・英語 4 文）で、日本語と英語の要約・重要な発言・文章の整形・誤認識の修正・翻訳を試しました（`Tests/SonaVantageAITests/LocalLLMIntegrationTests.swift`）。どのモデルも特別なトークンや思考を含まない回答を返し、検査を通った候補だけが残ることを確かめました。1 回の処理は 0.3〜10 秒程度でした（Phi-4 が最も遅い）。

- 気づいた点: Qwen3 1.7B は日本語の要約に中国語の字（「广告」）が混ざることがありました。誤認識の修正では、モデルによって「来週の会議出また報告します」を「会議出席報告します」のように誤って直す候補があり、検査（変更の大きさ・守る語）では止められない種類の誤りでした（正しく「会議でまた」と直したのは Ministral 3 3B・Gemma 4 E4B）。既定を「候補を確かめてから反映」にしているのはこのためです。
- 切り替えの確認: TinySwallow を読み込んだ後に Qwen3 1.7B に切り替えると前のモデルが解放され、解放後はプロセスのメモリが 1,042MB → 100MB に戻りました。
- 中止: 生成の途中で中止すると 0.01 秒以内に止まりました。
- 取得の中止と再開: Hugging Face から TinySwallow を取得し、338MB で中止 → 再開用のデータで 338MB から再開 → SHA-256 の照合まで通りました。
- 実際の録音の文字起こしでの、AI の修正・整形・要約の精度は確かめていません。

## 結果の編集・話者・要約

完了した結果は、右側の上部の「テキスト／区間（編集）」で表示を切り替えます。どの処理もこの Mac の中で行い、音声も文字も外部へ送りません。編集・確からしさ・ドラッグ＆ドロップ・ライブの品質表示は Air と Vantage の両方、フィラーの除去・誤認識の候補・話者・要約・AI の機能は Vantage だけです。

- **編集**: 「区間（編集）」で、区間ごとに文を直す（ダブルクリックまたは鉛筆のボタン。Return で確定、Esc で取り消し、空にすると削除）・削除する。認識した原文は書き換えずに残し、区間ごと・全体を「原文に戻す」で戻せます。書き出し・コピー・統合保存・ドラッグでの書き出しには、編集を反映した文を使います。再試行すると結果と一緒に編集も消えるので、その前に確認します。
- **フィラーの除去**: 「えー」「えーと」「あのー」「うーん」「um」「uh」などを、変わる区間を一覧で確かめてから取り除きます（後から原文に戻せます）。「あの人」「その件」のような語を消さないよう、「あの」「その」「まあ」は後ろに「ー」・読点・空白が続くときだけ消します。設定の「編集」で語を追加できます（前後が句読点・空白のときだけ消します）。
- **確からしさ**: 認識方式が値を返したときだけ、区間ごとの確からしさ（%）と、確からしさが低い語の下線を表示します。Whisper はトークン確率の平均、ReazonSpeech はトークンの対数確率から求めた確率の平均、Apple の音声認識は語句の confidence の平均です。正解率ではなく、モデル自身の確からしさです。値が返らない場合は何も表示しません。
- **誤認識の候補**: ①確からしさが低い語（基準は設定の「編集」で 30% / 50% / 70% 未満から選ぶ）、②同じ並びが何度も続く区間（Whisper の繰り返しの誤り）、③長さに対して文字が多すぎる区間（1 秒 25 文字超。無音から文を作る誤認識の兆候）を「要確認」として示します。「要確認のみ」で絞り込めます（Vantage）。AI のモデルが使える場合は、前後の文を手がかりにした修正案（ボタン）を出せます。置き換えるかどうかは利用者が選びます。
- **話者**: 「話者」から、声の特徴で話者を自動で分けます（pyannote segmentation-3.0 + 3D-Speaker CAM++ を sherpa-onnx で実行。初回だけ約 34MB のモデルを Hugging Face から取得）。話者ごとに色分けし（名前も必ず表示）、名前を付け、話者ごとの発言一覧・発言数・話した時間を表示します。区間ごとに話者を手で直せます。人数が分かっている場合は指定すると精度が上がります。音声全体を一度に読み込むため、2 時間までの音声に対応します。
- **要約・重要な発言**: 「要約・AI」から作ります。方法は 2 つです。
  - AI: 設定の「AI モデル」の選び方に従って、ローカルの言語モデルか Apple Intelligence（端末内のモデル）で全文を要約し、重要な発言を選びます。長い文字起こしは区切って要約してからまとめます。重要な発言は AI に番号を選ばせ、文は文字起こしのものをそのまま使います（AI が作った文を「発言」として出さないため）。同じ画面で翻訳もできます（原文は変えません）。文章の整形は編集画面の「AI 文章整形」に移しました。
  - 簡易抽出（AI なし）: 話題の中心になる語を多く含む文と、「決定」「期限」「お願い」「課題」「数値」などの語を含む文を、文字起こしから選びます（言い換えません）。どの Mac でも使えます。
  作った要約と重要な発言は、Markdown で書き出すと一緒に入ります。ライブ文字起こしの結果でも、終了後に作れます（ライブの結果の編集・話者識別には対応していません）。
- **ドラッグ＆ドロップ**: 結果の上部の「ドラッグで書き出し」を Finder などへドラッグすると、選んだ形式（txt / srt / vtt / md）のファイルとして書き出します（一時ファイルは終了時に削除）。キューの項目はドラッグで並べ替えられ、待機中の項目は上から順に処理します。
- **ライブ文字起こしの品質表示**: 取り込み中は、全体の状態（良好・遅れ気味・追いついていない）と、確定までの遅れ（話し終わりから文が確定するまで、直近 20 文の平均）、認識 1 回の処理時間、未処理の音声の長さ、確からしさ（Whisper が返したトークン確率の平均）を表示します。どれも測った値だけで、推測した値は出しません。

## 設定（⌘,）

- **一般**
  - 表示言語（下の「表示言語」を参照）
  - **自動開始**: 「ファイルを追加したらすぐに文字起こしを開始する」をオンにすると、ドロップや「ファイルを追加…」の時点で処理を始めます（既定はオフ）。処理中に追加したファイルは今の処理の続きで扱います。モデルが未取得などで開始できないときは、その理由をキューの上に表示します。
  - **Whisper の認識**: 「精度優先（Beam Search）」（既定。ビーム幅 5）と「速度優先（Greedy）」から選びます。Whisper を使うときだけ反映します。Apple M5 / Large v3 Turbo で 64 秒の日本語音声を試したところ、速度優先は約 15% 速く（2.4 秒 → 2.0 秒）、文章はほぼ同じでしたが、字幕の 1 区間が長くなりました（18 区間 → 8 区間）。
  - **設定のファイル**: 設定を JSON ファイルに書き出し・読み込みます（別の Mac への移行やバックアップ用）。読み込むときは項目ごとに値を確かめ、正しくない値・この Mac にない書体などは読み飛ばして件数を表示します。ゴーストモードと背景画像は含めません。
- **ライブ**: ゴーストモード（アプリ内の録音表示を隠す。既定はオフ）と、ライブ文字起こし中だけ効く停止・表示のショートカット（下の「ライブ文字起こし」を参照）
- **編集**: 確からしさの表示のオン・オフ（既定はオン）、「要確認」にする基準（30% / 50% / 70% 未満、既定は 50%）、追加のフィラー
- **通知**（既定はすべてオフ。オンにしたときに macOS の許可を求めます）: 一括の文字起こし・話者識別が終わったとき、ライブ文字起こしの入力が止まったとき、モデルのダウンロードが終わったとき。「Sona を使っているときは通知しない」（既定はオン）と「音を鳴らす」（既定はオフ）を選べます。
- **フォント**: 書体（インストール済みの書体から選択、既定はシステム標準）と文字の大きさ（小・標準・大・特大）。画面の文字と文字起こし結果の表示に使います。メニューなど macOS 標準の一部の部品は変わりません。保存するファイルには影響しません。
- **テーマ**
  - **外観**: システムに合わせる / ライト / ダーク
  - **背景**: 標準 / 色 / 画像。色の場合、外観が「システムに合わせる」なら背景色の明るさに合わせて文字の色（ライト・ダーク）を自動で選びます。
  - 画像の場合は**不透明度**（5〜100%、既定 30%）を指定できます。選んだ画像はアプリ専用のフォルダ（`~/Library/Containers/<Bundle ID>/Data/Library/Application Support/WhisperBatch/Background`）に複製するため、元のファイルを移動・削除しても背景は残ります。「削除」で複製も消えます。

## ライブ文字起こし

画面で再生中の動画やオンライン会議の音声を、この Mac の中で Whisper を使ってリアルタイムに文字起こしします。

- **メインウインドウから始める**: ツールバーの「ライブ文字起こし」（キューが空のときは中央の「ライブ文字起こし…」も同じ）を押すと、ライブ文字起こしのウインドウと開始前の確認画面が開きます。確認画面で対象・入力・音声の保存を確かめ（変更もできます）、「取り込みを開始」で始まります。
- メニューの「ライブ」→「ライブ文字起こしのウインドウを表示」（⇧⌘L）では、ウインドウだけを開きます。
- 取り込み中・一時停止中は、メインウインドウの上部に状態・経過時間・取り込んでいる入力と「一時停止／再開」「終了」「ライブの画面を表示」を表示し、ツールバーのボタンも「取り込み中 12:34」のように状態を示します。ボタンを押すとライブの画面に戻ります（取り込みの状態は変わりません）。終了後に保存していない結果があるときも、上部で知らせます。
- ライブ文字起こしのウインドウやメインウインドウを閉じても、取り込みは止まりません（止めるのは「終了」だけです）。

### 動作環境と必要な権限

| 項目 | 内容 |
| --- | --- |
| 対象 OS | macOS 27 以降（アプリ全体と同じ）。確認したのは macOS 27.2 / Apple M5 の 1 台です |
| 認識 | Whisper のみ（取得済みの Whisper モデルを選ぶ。既定は Large v3 Turbo）。応答の速さを優先して Greedy で認識し、結果が不確かなときは温度を上げて選び直します（whisper.cpp の標準の動き）。語彙のヒント（任意、最大 100 文字）を入力した場合は、手がかり（初期プロンプト）として渡します。認識言語は設定の言語（画面の表示言語とは別）を使います |

### 使い方

1. 「音声の入力」で使う入力をオンにします。3 つは独立してオン・オフできます。**マイクは初期状態でオフ**で、アプリを起動するたびにオフに戻ります。
   - **ウィンドウの音声**: 「ウィンドウを選ぶ…」で macOS の選択画面を開き、ウィンドウを 1 つ選びます。
   - **システム音声**: 「画面を選ぶ…」で画面を 1 つ選びます（映像は使いません）。
   - **マイク**
2. モデルと言語を選びます。必要なら「語彙のヒント」に人名・社名・専門用語を書きます（任意、100 文字まで）。「音声も保存する」をオンにすると、終了後に音声を保存できます（既定はオフ）。
3. 「確認して開始…」（またはメインウインドウの「ライブ文字起こし」）を押すと、確認画面が出ます。確認画面では、3 つの入力のオン・オフ、取り込む対象（ウィンドウ名とアプリ名、システム音声の範囲。「選び直す…」で変更可）、音声を保存するか、モデル・言語・語彙のヒントを確かめられます。対象を選んでいない・入力がない・モデルがない・ファイルの一括処理中など、始められないときは「取り込みを開始」を無効にし、その理由を横に表示します。「取り込みを開始」で始まります。
4. 取り込み中は、状態（取り込み中・一時停止・終了など）、経過時間（一時停止中は進みません）、入力ごとの名前・状態・音量、認識の状態（認識しています／音声を待っています）、知らせ・エラーを表示します。「一時停止」（⇧⌘P）・「再開」・「終了」（⇧⌘.）で操作します。
5. 終了後、「結果を保存」で TXT / SRT / WebVTT に書き出します（ファイルの一括処理と同じ形式。タイムスタンプの表示に合わせてテキストにも時刻を付けられます）。音声を保存する設定にしていた場合は「音声」→「音声を保存…」（WAV）または「音声を削除」を選びます。

### 暫定の文と確定した文

- 確定していない音声（最大 20 秒）を、新しい音声が 1 秒たまるごとにまとめて認識し直します。
- 0.6 秒以上の無音（話の切れ目）があると、そこまでの文を**確定**します。
- 0.6 秒に満たない短い間（会話の文と文・話者の交代など）でも、続けて 2 回の認識で同じ文・ほぼ同じ時刻になった区間は、末尾から 2 秒以上前に終わっていて、文の終わりの記号（。？！ など）で終わっているか、次の区間との境目に 0.15 秒以上の間（周りより静かな部分）があれば確定します。文の途中（間のない「、」の後など）では確定しません。
- それでも区切れないまま 20 秒に達したら、末尾付近の文だけを残して前を確定します。
- 次に読み直す音声の始まりは、区切りの近くで最も静かな位置に合わせ、暫定に残す文の頭より後ろでは切りません（語の頭を落とさないため）。
- 切れ目より前から始まっていても、時刻の範囲の半分以上が切れ目より後ろにある区間（Whisper が次の発話の開始時刻を早めに置いたもの）は確定せず、次の認識で読み直します。
- 確定済みの文と時刻が重なって始まり、その終わりと同じ語で始まる文は、重なった語を除いて確定します（同じ音声を読み直した重複を防ぐため。日本語などは 2 文字以上、英語などは 1 単語以上の一致）。時刻が重ならない言い直し（「どのくらい、どのくらいずれそうですか」など）や、フィラー（「えーと」「あの」）は除きません。
- 確定していない文は、［暫定］の印の後ろに灰色で表示します。続きを聞いて書き換わることがあります。通常の色の文字は確定した文で、以後は変わりません。確定した文は 1 区間 1 行で表示し、1 つの区間に複数の文が入っていれば文の終わりで行を分けます（分けた行の時刻は文字数で按分した目安です）。
- 一時停止・終了のときは、それまでの音声をすべて確定させてから止めます。
- 音量で簡易に発話を判定し、無音は Whisper に渡しません。ほとんど音のない部分（背景の雑音と同じくらいか、最も大きい部分より 20dB 以上小さい部分）の中だけにある文は、Whisper が無音から作った文（「はい」など）として捨てます。周りより静かなだけの部分（音楽の静かな所や小さな声）の文は捨てません。
- 確定した文は以後書き換えないので、読み直しで確定済みの文が変化することはありません。
- 認識が追いつかず、まだ一度も認識していない音声が 3 秒以上たまると、上部に「認識が遅れています（N 秒分を待っています）」と表示します。60 秒を超えた分は古い方から捨て、その秒数を知らせます。

### 認識の精度について（変更内容と測定）

ライブ文字起こしの認識の改善として、次の変更を入れました。どれも音声と結果をこの Mac の外へ出さず、保持する音声の上限（60 秒）も変えていません。

| 変更 | ねらい | 副作用 |
| --- | --- | --- |
| 間のない音声（音楽・早口）で、2 回続けて同じになった区間を、文の終わりか境目に間があるところで確定する | 確定が 20 秒の上限まで遅れ、長い 1 回の認識で崩れるのを防ぐ | 1 回の認識の重さは変わらない。文の途中では確定しないので、句読点のない長い発話では効果が小さい |
| 周りより静かなだけの部分（音楽の静かな所や小さな声）の文を捨てない。捨てるのは、ほとんど音のない部分の文だけ | 静かな部分の発話の取りこぼし（冒頭や小さな声の欠落）を防ぐ | 雑音の多い環境では、無音から作られた文が残る可能性が以前より少し増える |
| 区切りを、暫定に残す文の頭より後ろに置かず、近くの最も静かな位置に合わせる | 語の頭を落とさない | 読み直す音声がわずかに増える（計算量の差は測定で見えない程度） |
| 時刻が重なっていて文字も同じ確定文は、2 回目を足さない | 同じ音声を読み直したときの重複を防ぐ | 同じ文を本当に重ねて話した場合（時刻が重ならない限りは残る） |
| 1 つの区間に複数の文があれば、文の終わりで行を分ける | 行がまとまって読みにくくなるのを防ぐ | 分けた行の時刻は文字数で按分した目安 |
| 任意の「語彙のヒント」（100 文字まで）を Whisper の初期プロンプトとして渡す。区間の文字がヒント全体と同じ（2 語以上のヒントの丸写し）ときは、その区間を捨てる | 人名・社名・専門用語の誤認識を減らす | ヒントの語が、話されていないのに結果に出ることがある。伴奏下では効果が安定しない。ヒントと同じ語だけを並べて実際に話した場合も、その区間は捨てられる |

**測定の方法**: macOS の読み上げ音声（`say`、Kyoko / Samantha）で正解の分かる音声を作り、テスト（`Tests/WhisperBatchEngineTests/LiveQualityEvaluation.swift`）で実時間で流し込んで、確定した文を正解と比べました。数字の書き方（「十一月二十日」と「11月20日」）は正解側をそろえ、句読点と空白は除いて、文字（英語は単語）単位の誤り率を数えています。「伴奏あり」は、和音とリズムの合成音を声より 6dB 小さく重ねたものです。各条件 1 回ずつの測定です（Whisper は Metal 上で毎回まったく同じ結果になるとは限りません）。Apple M5、macOS 27.2、Large v3 Turbo（Q5_0）。

| 音声 | 変更前: 誤り率 / 確定までの遅れ 平均（最大） | 変更後 |
| --- | --- | --- |
| 会議風の日本語（73 秒、間 0.3〜1.5 秒） | 3.6% / 1.7 秒（2.8 秒） | 3.6% / 2.0 秒（5.6 秒） |
| 間の少ない日本語（73 秒） | 1.6% / 6.9 秒（12.4 秒） | 1.9% / 4.7 秒（9.7 秒） |
| 英語の会議風（35 秒） | 0.0% / 2.1 秒（6.2 秒） | 0.0% / 1.9 秒（4.3 秒） |
| 会議風の日本語＋伴奏 | 4.0% / 8.9 秒（16.5 秒） | 3.6% / 7.6 秒（15.6 秒） |
| 間の少ない日本語＋伴奏 | 1.6% / 9.1 秒（15.2 秒） | 1.6% / 7.3 秒（14.4 秒） |
| 会議風の日本語、語彙のヒントあり（「ミナト精機、カザハヤ研究所」） | ―（ヒントなしでは 2 語とも誤り） | 0.7%、2 語とも正しく認識 / 2.3 秒（7.4 秒） |
| 同上＋伴奏 | ― | 6.1%、1 語だけ正しく認識、言い誤りが 1 か所 / 10.1 秒（20.6 秒） |

- 1 回の認識は平均 0.41〜0.52 秒、最大 1.34 秒で、どの条件でも取りこぼしはありませんでした。
- 誤り率はほぼ変わらず、主に伴奏ありや間の少ない音声で、確定までの遅れが縮みました。会議風の日本語で遅れの最大値が 5.6 秒に伸びた件は、次の「会話・読み上げ向けの調整」で調べました。
- 語彙のヒントは、話し声では固有名詞の誤りを直しました。伴奏下では効果が安定せず、言い誤りも出ました。

#### 会話・読み上げ向けの調整

ライブ文字起こしは、**会議のような自然な会話**と、**リスニング問題のような明瞭な読み上げ**を主な用途として調整しています（歌声・伴奏下の歌詞は優先目標にしていません）。

測定用に、2 つの声で短い間・言いよどみ（「えーと」「あの」）・言い直しを含む会話風の日本語（75 秒）、設問・選択肢の間に 1〜2.5 秒の無音がある英語（65 秒）と日本語（62 秒）のリスニング問題風の音声を、読み上げ音声で作りました。評価のテストは、確定ごとに理由（切れ目・2 回一致・上限・終了）と遅れを記録し、中央値・95 パーセンタイル・最大値、文字が画面に出るまでの遅れ、認識時間、捨てた音声（発話なしとして読まなかった分と、処理が追いつかずに捨てた分）を分けて出します。

**遅れの原因として確認したこと**（以前の会議風の音声で最大 5.6 秒になった件）:

- 認識の処理待ちは最大 1.3 秒、処理が追いつかずに捨てた音声は全条件で 0 秒、1 回の認識は中央値 0.40〜0.45 秒で、処理の詰まりは原因ではありませんでした。
- 遅かった確定は 2 つの型でした。(1) 文と文の間が短く（0.3 秒）、Whisper が文末の「。」を付けず、区間の分け方も認識のたびに変わったため、次の長めの間まで確定できなかったもの。(2) 文の途中の断片（「月曜日は全体会議」）が文全体より先に確定したもの。(2) は文全体が話し終わりから 1.4 秒で確定しており、区間の終わりから数える指標の性質による見かけの遅れです。
- 会話風の音声の誤りの多くは、Whisper が次の発話の開始時刻を切れ目より前に置いたために、確定した語の音声をもう一度読み、「じゃあ / じゃあ、その前に…」のように重複したものでした。

**変更**: 2 回一致による確定で 0.15 秒以上の短い間を境目として認める／切れ目をまたいで大半が後ろにある区間は読み直す／確定済みの文と時刻が重なって始まる語を除く／ヒントの丸写しの区間を捨てる／認識が遅れているときに待っている秒数を表示する。

各条件 1〜2 回の測定です（Apple M5、macOS 27.2、Large v3 Turbo（Q5_0）、読み上げ音声）。誤り率は数字の書き方をそろえた値、遅れは「一緒に確定した区間のうち最後の区間の終わり」から確定までです。

| 音声 | 変更前: 誤り率 / 遅れ 中央・p95・最大 | 変更後 |
| --- | --- | --- |
| 会話風の日本語（1 回目） | 5.7% / 1.6・3.6・3.6 秒 | 2.4% / 1.7・3.9・3.9 秒 |
| 会話風の日本語（2 回目） | 5.1% / 1.6・3.3・3.3 秒 | 2.1% / 1.9・3.5・3.5 秒 |

| 会議風の日本語（1 回目） | 3.6% / 1.7・2.3・2.3 秒 | 3.6% / 1.5・4.4・4.4 秒（(2) の型） |

| 日本語のリスニング | 5.9% / 1.5・2.6・2.6 秒 | 5.3% / 1.4・3.4・3.4 秒 |

- 文字（暫定を含む）が画面に出るまでの遅れは、変更の前後とも中央値 0.5〜0.8 秒、最大 1.1〜1.9 秒でした。
- 発話なしとして読まずに捨てた音声は 1.4〜4.7 秒（無音の区間）、処理が追いつかずに捨てた音声はすべて 0 秒でした。
- 誤りは会話風の音声で減りました（重複が消えたため）。読み上げ音声では誤り・遅れとも測定ごとのばらつきの範囲でした。会議風の音声で最大の遅れが 4〜5 秒になる場合は、(1) の型が測定によって出たり出なかったりし、**解消していません**。
- 英語のリスニングの誤りの多くは、選択肢の記号を Whisper が「Be」「See」と聞き取ったもの（B・C）と数字の書き方（「ten fifteen」→「10.15」）です。
- 言いよどみ（「えーと」「うーん」）や言い直しは、Whisper が出したとおりに残し、アプリでは削除・整文しません（Whisper 自身が言いよどみを省くことはあります）。
- 話者を区別する機能はありません。話者の交代は、間や文末で行が分かれることが多いものの、1 行にまとまる場合もあります。
- 試したが採用しなかったもの: 話の切れ目とみなす無音を 0.6 秒から 0.45 秒に短くする設定。会話風の音声とリスニングで遅れが縮んだ回もありましたが、各 1 回の測定で根拠が弱く、言いよどみで文が細切れになるおそれがあるため、0.6 秒のままにしました。
- 入力の変換（48kHz ステレオ → 16kHz モノラル）で音量が変わらないこと（左右の平均）と、呼び出しを重ねても音声が失われないことをテストで確かめました。実際の 2 つの声を同時に鳴らした確認では、通常の大きさで 0.8 を超えたのは全体の 0.02% で、その部分だけをなめらかに抑え、出力は 1 未満に収まりました。
- 人の声・実際の会議・会議アプリやマイクの音声での精度と遅れは、確認していません。

試したが採用しなかったもの:

| 試したこと | 結果 | 判断 |
| --- | --- | --- |
| 直前に確定した文（最大 60 文字）を手がかりとして渡す | 誤り率は下がらず、Whisper が複数の文を 1 区間にまとめる（16 行 → 11 行）、文の途中で続きを推測して補う・語が重複する（間の少ない日本語で 1.6% → 4.7%）ことが増えた | 使わない（コードには既定でオフの選択肢として残し、測定に使う） |
| ビーム探索（幅 5）で認識する「精度優先」 | 会議風の日本語は同じ 3.6%、伴奏ありは 3.6% → 4.7%、認識時間は約 1 割増 | 根拠がないので、精度優先の切り替えは設けない |
| 小さな音声を認識前に持ち上げる | -20dB（中央値 -44dBFS）の音声でも、変更前から通常の音量と同じ誤り率だった | 効果の根拠がないので入れない |

- 音量で発話を判定する下限（約 -50dBFS）より小さい音声は、変更の前後とも認識しません（読み上げ音声を 30dB 下げると、ほとんど認識されませんでした）。雑音を発話と誤らないための下限で、変えていません。
- **歌・音楽について**: Whisper は、歌声や、伴奏・効果音と重なった声を、普通の会話より誤りやすく、繰り返しの多い部分を数え間違えたり飛ばしたりすることがあります。このアプリは、曲名から歌詞を補ったり、既知の歌詞に置き換えたり、外部の歌詞サービスに照合したりはしません。上の測定の「伴奏」は合成音で、実際の歌声は測っていません。依頼時に触れられていた楽曲の文字起こし例は手元になく、その曲での比較はしていません。
- 測定は合成音声によるもので、実際の会議・配信・人の声での精度を保証するものではありません。

### 音声の取り込み範囲（macOS 27.2 で確認した動き）

周波数の違う試験音を鳴らす 3 つのアプリ（2 つのウィンドウを持つアプリ、別のアプリ、ウィンドウのないアプリ）を用意し、ScreenCaptureKit の取り込みで、どの音が入るかを測りました。

| 選んだ対象 | 入った音 |
| --- | --- |
| ウィンドウ | **そのウィンドウを持つアプリ全体の音**。同じアプリのもう 1 つのウィンドウの音も入りました。ほかのアプリ・ウィンドウのないアプリの音は入りませんでした |
| 画面（システム音声） | ウィンドウのないアプリも含めたすべてのアプリの音（このアプリ自身の音は除く設定） |

- **ウィンドウを選んでも、そのウィンドウだけの音にはなりません。** 同じアプリの別のウィンドウやタブの音も入ります。画面と確認画面にもそう表示しています。
- macOS は音を出しているプロセスを、そのプロセスを起動したアプリにまとめることがあります（試験ではターミナルから直接起動したプログラムの音が、ターミナルの音として扱われました）。ブラウザーなどが別プロセスで再生する音がどう扱われるかは確認していません。
- 出力をミュートしていても取り込めました（音量の設定の影響を受けません）。
- システム音声とウィンドウの音声を両方オンにした場合、システム音声にウィンドウの音も含まれるため、システム音声だけを取り込みます（同じ音を二重に混ぜません）。マイクは画面側の音と足し合わせます。

### 取り込み中に起きることへの対応

| できごと | 対応 |
| --- | --- |
| 選んだウィンドウが閉じられた | アプリが動いている間は ScreenCaptureKit が音を渡し続けるため（確認済み）、ウィンドウの有無を 1 秒ごとに確かめ、なくなったら取り込みを止めて知らせます。ほかに入力がなければ一時停止します。最小化などで見えないだけのときは「画面に表示されていません（アプリの音声は取り込み続けます）」と表示します |
| 対象のアプリが終了した | ScreenCaptureKit がエラー -3815 で止まります（確認済み）。取り込みを止めて知らせます |
| macOS のメニューから共有が止められた | 取り込みを止めて知らせます |
| マイクが外された・切り替わった | 新しい入力機器で取り込み直し、切り替わったことを知らせます。使える入力がなければマイクの取り込みを止め、再開時にもう一度試します |
| 入力がすべてなくなった | 一時停止します |
| 認識が追いつかない | 保持する音声は最大 60 秒で、超えた分は古い方から捨て、捨てた秒数を表示します |
| 空き容量がなくなった（音声を保存する場合） | 音声の保存だけをやめ、文字起こしは続けます |

### 長時間の利用とメモリ

- 音声はメモリ上で扱い、確定した分は捨てます。保持する音声は、入力ごとのバッファが最大 10 秒、認識を待つ音声が最大 60 秒（通常は 20 秒程度）で、時間がたっても増えません。
- 増えるのは確定した文字だけです（1 時間の会話で 100 KB 前後）。表示は確定した文を末尾に足すだけにしています。
- 3 時間分を流すシミュレーションと、実時間より速く音声を流し込むテストで、保持する音声が上限を超えないことを確かめています。実際に何時間も取り込み続ける試験はしていません。

### ゴーストモード（アプリ内の録音表示を隠す）

ゴーストモードは、**利用者が明示的に選んだときだけ**、このアプリ自身が出す録音中の表示とウインドウを隠す機能です。

- 設定（⌘,）の「ライブ」タブにある「アプリ内の録音表示を隠す」で切り替えます。**初期状態はオフ**です。オンにしようとすると、何が隠れて何が隠れないかを説明する確認が出て、「有効にする」を押したときだけ有効になります。アプリが自動で有効にすることはありません。
- 有効にすると:
  - ライブ文字起こし中に、メニューバーに出すこのアプリの「取り込み中」のアイコンを出しません（オフのときは、取り込み中・一時停止中にこのアイコンを出し、そこから一時停止・終了・表示ができます）。
  - ライブ文字起こしのウインドウに「隠す」ボタンが出ます（メニューの「ライブ」→「ウインドウを隠す（ゴーストモード）」、⌃⌘H も同じ）。押したときだけ、このアプリのウインドウを隠します。
- 隠しても、取り込みは止まりません。また、取り込みの開始・停止と、表示を隠すかどうかは別の操作です。
- **macOS が出す表示には触れません。** 画面収録やマイク使用中を示す macOS のメニューバーの表示（紫・オレンジのアイコンなど）は、ゴーストモードでもそのまま出ます（ゴーストモードのオン・オフどちらでも、画面収録の表示が出ていることを確認しました）。Dock のアイコンも隠しません。
- **表示に戻す方法**: Dock のアイコンを押す／Dock のアイコンを右クリックして「ウインドウを表示」／メニューの「ライブ」→「ウインドウを表示」／表示ショートカット（既定 ⌃⌥⌘L）。
- **状態を確かめて止める方法**: Dock のアイコンを右クリックすると、状態（例: 「取り込み中 12:34（ウインドウは非表示）」）と「一時停止」「終了」「ウインドウを表示」が出ます。メニューの「ライブ」にも状態と「終了」があります。停止ショートカット（既定 ⌃⌥⌘S）は、ほかのアプリを使っているときにも効きます。
- ショートカットは設定の「ライブ」タブで決まった候補から選べます（停止: ⌃⌥⌘S / ⌃⌥⌘. / ⌃⌥⌘X / なし、表示: ⌃⌥⌘L / ⌃⌥⌘W / ⌃⌥⌘O / なし）。取り込み中・一時停止中だけ登録し、ほかのアプリが使っていて登録できなかったときは設定画面で知らせます。Carbon の `RegisterEventHotKey` を使うため、アクセシビリティの許可は不要です。
- ゴーストモードをオフにすると、隠していたウインドウは表示に戻ります。アプリを終了しようとしたときも、確認の前に表示に戻します。

### 音声データの保存・送信

- 音声も認識結果も、外部へ送信しません（通信するのはモデルのダウンロード時だけです）。
- 音声をファイルに書くのは、開始前に「音声も保存する」をオンにしたときだけです。その場合、取り込んだ音声（Whisper に渡したものと同じ 16kHz モノラル）をアプリ専用の一時フォルダ（`<一時フォルダ>/Sona-Live/<プロセスごとのフォルダ>/`、1 時間あたり約 115 MB）に書き、終了後に利用者が選んだ場所へ移します。保存しなかった一時ファイルは、「音声を削除」・新しいセッション・アプリの終了のいずれかで削除し、異常終了で残ったものは次回の起動時に削除します。開始前に 1 時間分の空きがあるかを確かめます。
- 一時フォルダはアプリのプロセスごとに分け、所有者だけが読み書きできるようにしています（フォルダ 0700・ファイル 0600、名前は推測できない UUID、既存のファイルは開かず新しく作る）。アプリの終了時は自分のフォルダだけを消し、起動時の後片付けは**終了したプロセスのフォルダだけ**を消します。同じアプリの別のコピーや、Bundle ID を共有する旧版が同時に動いていても、録音中のファイルは消しません。プロセスが動いているかは PID ではなく、フォルダごとのロックファイルの排他ロック（`flock`。プロセスが終わると異常終了でも OS が外す）で判断するので、PID の再利用の影響を受けません。判断できないときは消さない側に倒れます。
- 文字起こしの結果は、利用者が「結果を保存」を選んだときだけファイルに書きます。保存していない結果があるときは、新しいセッションの開始やアプリの終了の前に確認します。
- アプリが予期せず終了した場合: ScreenCaptureKit の取り込みと AVAudioEngine のマイク入力はアプリのプロセスに属するため、プロセスの終了とともに止まります（OS の仕組み。異常終了させての確認はしていません）。メモリ上の音声と結果は失われ、一時フォルダに残った音声は次回の起動時に削除します（同時に動いている別のプロセスのものは消しません）。

## 動画の文字起こし（変換方式）

動画を追加すると、通常の一括処理の中で次の順に処理します。利用者が変換操作をする必要はありません。

1. AVFoundation で動画を開き、映像トラックの有無と音声トラックを確認する
2. 最初の音声トラックを AVFoundation でデコードし（44.1 kHz、ステレオ以上は 2ch・モノラルは 1ch）、**LAME で MP3（128 kbps 固定）に変換**して一時ファイルに書く
3. その MP3 を Whisper で文字起こしする（音声ファイルと同じ処理）
4. 一時 MP3 を削除する（成功・失敗・キャンセルのどの場合も）

### 方式を選んだ理由

- **macOS には MP3 エンコーダーがありません**。macOS 27 の AudioToolbox でエンコードできる形式を実機で調べた結果、AAC・ALAC・FLAC・Opus・PCM などはありましたが MP3 はありませんでした。そのため、動画からの音声の取り出しとデコードは標準の AVFoundation で行い、MP3 化だけに外部ライブラリを使っています。
- **LAME を選んだ理由**: MP3 エンコーダーとして定番で、C のソースだけでできていて arm64 向けに SwiftPM で直接ビルドでき、アプリのプロセス内で動くので App Sandbox でも問題なく使えます。ライブラリは約 0.26 MB です。
- **FFmpeg を採用しなかった理由**: Homebrew の FFmpeg（9.0.2）は GPL-3.0-or-later でビルドされており、ライブラリのフォルダだけで約 40 MB（ほかに依存パッケージが 11 個）と配布サイズが大きく、別プロセスとして実行するにはサンドボックス用の署名・権限設定が必要です。必要なのは MP3 エンコードだけなので過剰と判断しました。
- 認識に使う音声を MP3 にすると、元の音声を直接読むより音質はわずかに落ちます（不可逆圧縮のため）。128 kbps では文字起こしの結果に差は見られませんでした（テスト音声での確認）。

### 一時ファイル

- 置き場所: アプリの一時フォルダ（サンドボックスのコンテナ内）の `Sona-Conversions/<プロセスごとのフォルダ>/`（ライブ文字起こしの一時ファイルと同じ方式。上記「音声データの保存・送信」）
- 処理が終わる・失敗する・キャンセルされると、その都度削除します。アプリの終了時には自分のフォルダを消し、異常終了した場合の残りは次回の起動時に消します。別のコピーや旧版が同時に動いていても、処理中のファイルは消しません。
- 変換前に、出力先の空き容量が足りるか確認します（目安: 1 分あたり約 1 MB）。足りない場合は変換せずにエラーを表示します。
- 元の動画は読み込むだけで、変更・移動・削除はしません。

### 動画の対応形式（macOS 27.0.1 で確認）

| 結果 | 形式 |
| --- | --- |
| 変換・文字起こしできる | MP4（H.264 / HEVC、AAC 音声）、MOV（AAC / ALAC / リニア PCM 音声、ProRes 映像を含む）、M4V、3GP、MPEG-2 プログラムストリーム（.mpg）、MPEG-2 トランスポートストリーム（.ts） |
| 複数の音声トラックがある動画 | 最初の音声トラックを使います |
| 音声のない動画 | 「macOS で読み込める音声が見つかりません」と表示 |
| MP4 に MP3 音声を入れたもの | AVFoundation が音声トラックとして認識しないため、上と同じエラーになります |
| 読み込めない | MKV（追加時に対象外）、WebM、AVI（追加直後に「対応していない形式」と表示） |

上記以外（WMV、FLV、.mts / .m2ts など）は確認していません。追加はできますが、macOS で読めない場合はエラーになります。

## 音声の対応形式

WAV、MP3、M4A（AAC / ALAC）、AAC（ADTS）、AIFF、CAF、FLAC、Ogg Vorbis/Opus（.ogg / .opus）を実ファイルで確認しました。ステレオ・48 kHz なども 16 kHz モノラルに変換して処理します。WebM 音声は読み込めません。

## 表示言語（日本語・英語）

- **初期設定**: macOS の優先言語（システム設定 > 一般 > 言語と地域）の並びで、日本語と英語のうち先にある方を使います。どちらもなければ英語です。
- **切り替え方**: メニューの「Sona > 設定…」（⌘,）で「システムに合わせる / 日本語 / English」を選びます。画面の文字はすぐに切り替わり、選択は次回起動後も保持されます。
- ファイル・編集・ウインドウなど macOS 標準のメニュー項目や、保存ダイアログのボタンは、次回起動時に切り替わります（このアプリ用の `AppleLanguages` 設定を書き換えています）。
- **文字起こしの言語は別の設定**です。表示を英語にしても、認識する言語（日本語・自動判定・英語など）は変わりません。
- 文字列は `Localization/ja.lproj/Localizable.strings` と `Localization/en.lproj/Localizable.strings` にまとめてあり、Swift からは `L("キー")` で参照します。テキストエディタで編集でき、ビルド時に `.app` の Resources にコピーされます。`swift run` などで直接実行する場合は、環境変数 `WHISPER_BATCH_LOCALIZATION_DIR` に `Localization` フォルダを指定してください。
- OS が返すエラーの説明（ファイルが破損している場合など）の一部は、macOS の言語で表示されることがあります。

## アニメーション

操作の分かりやすさのための短い動き（0.12〜0.22 秒）だけを使い、点滅や大きな拡大縮小はしません。設定は `Sources/WhisperBatch/Views/Motion.swift` にまとめています。

| 操作 | 動き | 「視差効果を減らす」が有効なとき |
| --- | --- | --- |
| ファイルの追加・削除 | キューの行が短くフェードし、少しスライドして出入りする | フェードのみ |
| 状態の変化 | 状態アイコンが入れ替わり、完了・失敗時に 1 回だけ小さく弾む | 即座に切り替え、弾まない |
| 進捗の数字 | ％の数字が滑らかに切り替わる | 即座に切り替え |
| 変換 → 文字起こし | 処理中の表示のラベルがクロスフェードで入れ替わる | 即座に切り替え |
| ドラッグ中 | ウィンドウの強調表示と案内がフェードで現れる・消える | 即座に表示 |
| 結果表示・下部のバナー | 状態が変わると結果表示がクロスフェード、下部のバナーは下からフェードで入れ替わる | 透明度の変化のみ |

- 「視差効果を減らす」は macOS のシステム設定（アクセシビリティ > 表示）に従います。
- 開発時は、システム設定を変えずに `WHISPER_BATCH_REDUCE_MOTION=1 "build/Sona.app/Contents/MacOS/Sona"` で起動すると、「視差効果を減らす」の表示を確認できます。
- 画面録画をコマ送りして、通常時の動き（行のフェード、アイコンの弾み、ラベルのクロスフェード、強調表示のフェード、バナー）と、「視差効果を減らす」の表示（アイコンが弾まない）を確認しました。VoiceOver などの支援技術との組み合わせは試していません。

## 文字起こしの方式

メイン画面の「方式」で Whisper / ReazonSpeech / Apple を切り替え、「モデル」でその方式のモデル（サイズ）を選びます。「モデル管理…」も方式ごとに一覧を切り替えられます。方式を切り替えて戻ると、前にその方式で選んでいたモデルに戻ります。

| 方式 | 言語 | モデルの選択肢 | 取得元 | 特徴 |
| --- | --- | --- | --- | --- |
| Whisper | 多言語（自動判定あり） | Tiny 〜 Large v3 の 7 種類 | Hugging Face（ggerganov/whisper.cpp） | 精度が高い。大きいモデルほど遅い |
| ReazonSpeech | 日本語のみ | 軽量（int8、160 MB）／高精度（615 MB） | Hugging Face（reazon-research/reazonspeech-k2-v2） | 日本語に特化。非常に速い（1 分の音声を数秒） |
| Apple | 言語を選んで使う（自動判定なし） | SpeechTranscriber／DictationTranscriber | macOS（言語データは OS が管理） | ダウンロード不要で速い。句読点付き |

### Whisper


**whisper.cpp の公式 XCFramework** を Swift Package の `binaryTarget` として使い、C API を Swift から直接呼んでいます。完全にローカルで動き、Metal で GPU を使え、MIT License です。OpenAI の Whisper API（音声の外部送信が必要）、WhisperKit（依存が多く Core ML 用モデルが別途必要）、Homebrew の whisper-cpp（アプリ単体で完結しない）は採用していません。

長時間の音声は 16 kHz モノラルで少しずつ読み出し、10 分ごとのチャンクで認識します。チャンクの境界は末尾付近の最も静かな位置に合わせ、境界で切れた区間は次のチャンクで読み直すので、文の途中で切れたり重複したりしにくくなっています。

### ReazonSpeech

株式会社レアゾン・ホールディングスが公開している日本語の音声認識モデル（Zipformer RNN-T、Apache License 2.0）を、k2-fsa の公式 XCFramework（`sherpa-onnx`、ONNX Runtime を内包）で動かします。モデルは公式リポジトリの ONNX ファイルを、公開時のコミットに固定して取得し、ファイルごとに SHA-256 を検証します（コードを含みうる pickle 形式のファイルは使いません）。

このモデルは 1 つの発話を前提にしているため、複数の文をまとめて渡すと一部の文を出力しないことがあります（合成音声での試験で確認）。そのため、音声を文の間の無音（0.25 秒以上）で区切り、1 発話ずつ（最長 10 秒）認識します。各発話の前後には公式ライブラリと同じく 0.9 秒の無音を足します。出力に句読点は付かず、1 発話が 1 行（1 区間）になります。

### Apple（macOS 標準の音声認識）

- **SpeechTranscriber**（おすすめ）: 長い音声の文字起こし向け。**DictationTranscriber**: macOS の音声入力と同じ方式。
- モデルのサイズは選べません。言語ごとのデータを macOS が Apple のサーバーから取得して管理し、ほかのアプリと共有します。このアプリからは削除しません。
- 言語ごとに最初に「言語データを取得…」が必要です（取得済みなら不要。英語は最初から入っていることが多い）。言語の自動判定はないので、Apple を選ぶと「自動判定」は使えません。
- 結果は語句ごとの時刻を使って文単位の区間にまとめ直します。

## モデルの取得と保存

モデルはアプリに同梱していません。利用者が確認ダイアログで同意したときだけ、Hugging Face からダウンロードし、ファイルごとに SHA-256 を検証してから保存します。

**話者識別**（「話者」の画面またはモデル管理の「話者識別」から取得。保存先は `Models/speaker-diarization/`、合計 34.3 MB）: `huggingface.co/csukuangfj/sherpa-onnx-pyannote-segmentation-3-0`（コミット `9403a69`、`model.onnx` 5.99 MB、MIT）と `huggingface.co/csukuangfj/speaker-embedding-models`（コミット `0743f30`、`3dspeaker_speech_campplus_sv_zh_en_16k-common_advanced.onnx` 28.3 MB、Apache-2.0）。文字起こしのモデルの一覧には出ません。

**Whisper**（`huggingface.co/ggerganov/whisper.cpp`、コミット `5359861` に固定）

| モデル | ファイル | サイズ | 必要な空き容量の目安 |
| --- | --- | --- | --- |
| Tiny | ggml-tiny.bin | 77.7 MB | 約 128 MB |
| Base | ggml-base.bin | 148 MB | 約 198 MB |
| Small | ggml-small.bin | 488 MB | 約 538 MB |
| Medium | ggml-medium.bin | 1.53 GB | 約 1.69 GB |
| **Large v3 Turbo（Q5_0）** | ggml-large-v3-turbo-q5_0.bin | 574 MB | 約 631 MB（**既定**） |
| Large v3 Turbo | ggml-large-v3-turbo.bin | 1.62 GB | 約 1.79 GB |
| Large v3 | ggml-large-v3.bin | 3.10 GB | 約 3.40 GB |

**ReazonSpeech**（`huggingface.co/reazon-research/reazonspeech-k2-v2`、コミット `291488c` に固定）

| モデル | ファイル | サイズ | 必要な空き容量の目安 |
| --- | --- | --- | --- |
| **軽量（int8）** | encoder / decoder / joiner の int8 版 + tokens.txt | 160 MB | 約 210 MB（**ReazonSpeech の既定**） |
| 高精度 | encoder / decoder / joiner + tokens.txt | 615 MB | 約 676 MB |

- 保存先: `~/Library/Containers/com.example.WhisperBatch/Data/Library/Application Support/WhisperBatch/Models/`（「モデル管理…」の「Finder で表示」で開けます）。Whisper はこの直下、ReazonSpeech はモデルごとのフォルダに置きます。
- 複数ファイルのモデルは 1 ファイルずつ取得・検証し、途中で失敗しても検証済みのファイルは取得し直しません。
- 切り替え・削除: メイン画面のモデル選択、または「モデル管理…」
- 通信エラーで失敗した場合は「再開」で途中から、それ以外は「再試行」で最初から取得し直します。
- 受信中も、受け取った量（再開した場合は再開位置からの分を足した全体の量）がカタログの大きさを超えた時点で受信を止めます。応答が宣言する大きさがカタログより大きい場合や、エラーの応答（HTTP 200 番台以外）も、受け取り続けずに止めます。完了後は、SHA-256 を計算する前に大きさがカタログと一致するかを確かめます。
- 失敗（エラーの応答・大きさの超過や不一致・SHA-256 の不一致・保存の失敗）と中止のどの場合も、検証前のファイル（`<ファイル名>.download`）を残しません。利用者が中止した場合だけ「中止」と表示し、それ以外は失敗の理由を表示します。
- 取得済みかどうかは、ファイルがあって大きさが一致するかで判断します（一覧の表示のたびに内容を読むと遅いため）。そのうえで、**モデルを読み込む直前に、内容の SHA-256 をカタログの値と照合**し、一致しなければ読み込まずに「モデルを削除して再ダウンロード」を案内します（同じ大きさのまま書き換えられた・壊れたファイルを検出するため）。照合の時間は、この Mac（M5）で約 2.6 GB/秒（Large v3 Turbo（Q5_0）で約 0.2 秒、Large v3 Turbo で約 0.6 秒、Large v3 で約 1.1 秒。同じ大きさのファイルでの測定）です。
- 一度照合したファイルは、アプリを終了するまで、ファイルの同一性（デバイス・inode・大きさ・更新時刻・状態変更時刻）が変わらない限り照合し直しません。書き換え・置き換え・属性の変更のどれかがあれば照合し直します。照合の結果はディスクに保存しません（保存すると、モデルを書き換えられる者がその記録も書き換えられるため）。照合してから whisper.cpp などが読み込むまでの間に置き換えられた場合は検出できません。

## 出力形式

| 形式 | 内容 |
| --- | --- |
| テキスト (.txt) | 認識区間ごとに 1 行。オプションで各行にタイムスタンプ。話者識別をした場合は行の頭に話者名 |
| SRT (.srt) / WebVTT (.vtt) | 字幕形式（WebVTT の本文中の `-->` は `→` に置き換え）。話者名は SRT では本文の頭、WebVTT では `<v 話者名>` |
| Markdown (.md) | 見出し（ファイル名）・言語・長さ・話者・要約・重要な発言（作った場合）・本文（話者名とタイムスタンプは太字）。本文の記号は Markdown として解釈されないようにエスケープ |
| 統合ファイル (.txt) | 各結果を `[番号/件数] ファイル名` の見出しで区切り、指定した順に並べる（統合はテキストのみ） |
| MP3（動画の音声） | 「音声を MP3 で保存…」を選んだときだけ。128 kbps、44.1 kHz |

UTF-8（BOM なし）・LF で、一時ファイル経由で置き換えるため書き込みに失敗しても既存ファイルは壊れません。保存先は必ずダイアログで選び、既存ファイルの上書きは確認します。音声なしの場合の本文（「音声が検出されませんでした」）と統合ファイルの既定名は、表示言語に従います。

## プライバシー

- 文字起こしと動画の変換はすべてこの Mac 上で行います。音声・動画・認識結果・利用状況を外部へ送信しません。
- AI の処理（誤認識の修正・文章の整形・要約・重要な発言・翻訳・修正案）は、この Mac に取得したローカルの言語モデル（llama.cpp）か、Apple Intelligence の端末内のモデル（Private Cloud Compute は使わない）か、AI を使わない簡易抽出で行い、文字起こしを外部へ送りません。話者識別もこの Mac の中で行います。ローカルの言語モデルの取得は、文字起こしのモデルと同じく `huggingface.co` からだけ、利用者が選んだときだけ行います。
- 通知（既定はすべてオフ）には、ファイル名と処理の結果の概要だけを入れ、文字起こしの文は入れません。
- 設定の書き出しファイル（JSON）には、ゴーストモード・背景画像・モデル・文字起こしの結果・ファイルの場所を含めません。語彙のヒントと追加のフィラーは含みます。
- 通信するのはモデルのダウンロード時だけで、送るのはファイルの取得要求（`huggingface.co` への HTTPS GET）だけです。ダウンロード前に確認ダイアログを表示します。
- 接続先は `huggingface.co` と `hf.co`（ファイルの実体の配信元。例: `us.aws.cdn.hf.co`）とそのサブドメインに、HTTPS でのみ限っています。最初の URL だけでなく、リダイレクト先と、中断したダウンロードの再開先も確かめ、それ以外への接続は中止します（公衆 Wi-Fi のログインページへの転送などで起こります）。Apple の言語データは macOS が Apple のサーバーから取得します（取得前に確認ダイアログを表示）。
- Apple の音声認識（SpeechAnalyzer）は、Apple の説明では音声をサーバーに送らずこの Mac の上で処理します。言語データ（認識に使うモデル）の取得は macOS が行うもので、このアプリ自身の通信（Hugging Face からのモデルのダウンロード）とは別です。このアプリは言語データの取得を macOS に頼むだけで、その通信の内容には関わりません。
- App Sandbox を有効にしています。読み書きできるのは、利用者が選択・ドロップしたファイルと、保存先として選んだ場所、アプリ自身のコンテナだけです。選択・ドロップしたファイルには読み取り専用のセキュリティスコープ付きブックマークを作り、処理している間だけアクセスを開始して、終わったら解放します。ファイルの移動などでブックマークが古くなっていた（stale）場合は、アクセスしている間に作り直してキューの項目に反映します。
- ネットワークの権限は、接続を受け付けない「送信側（client）」だけです（`com.apple.security.network.client`）。モデルのダウンロードに必要な最小限で、サーバーとして待ち受ける権限は付けていません。
- 変換用の一時 MP3 は処理後に削除し、利用者が「音声を MP3 で保存…」を選んだときだけ、選んだ場所に保存します。
- ライブ文字起こしの音声はメモリ上で処理し、利用者が「音声も保存する」を選んだときだけ一時ファイルに書きます（上記「音声データの保存・送信」）。取り込む対象は macOS の選択画面で利用者が選び、マイクは利用者がオンにしたときだけ使います。
- whisper.cpp のログは出力しません（開発時の調査用に `WHISPER_BATCH_VERBOSE=1` で標準エラーに出せます）。API キーなどの秘密情報は使っていません。

### Hardened Runtime での動作（確認結果）

`scripts/build-app.sh` の既定の署名（アドホック署名）は、Hardened Runtime を有効にしていません（`WB_SIGN_IDENTITY` を指定したときだけ有効にします）。Hardened Runtime を有効にした署名について、このアプリのコピーで次のことを確認しました（この Mac にはコード署名用の証明書がないため、すべてアドホック署名での確認です）。

| 署名の組み合わせ | 結果 |
| --- | --- |
| アドホック署名 + Hardened Runtime | **起動しません**。ライブラリ検証により `libLAME.dylib` の読み込みが「プロセスと Team ID が異なる」として拒否されます（アドホック署名には Team ID がないため） |
| アドホック署名 + Hardened Runtime + `com.apple.security.cs.disable-library-validation` | 起動し、`whisper.framework` と `libLAME.dylib` が読み込まれ、動画と音声の文字起こしができました |
| Developer ID 署名（アプリとライブラリを同じ Team ID で署名）+ Hardened Runtime | **未確認**（証明書がないため）。Apple の仕様上は同じ Team ID のライブラリは読み込まれますが、その場合、利用者が差し替えたライブラリは読み込まれません |

Developer ID で配布する場合の方針:

- **通常の配布ビルドでは `disable-library-validation` を付けません。** 同梱ライブラリとアプリを同じ証明書（同じ Team ID）で署名すれば、Apple の説明上、Hardened Runtime のライブラリ検証のもとでも読み込まれます（この組み合わせは上の表のとおり未確認）。
- `com.apple.security.cs.disable-library-validation` は、Apple・同じ Team ID 以外が署名したライブラリ（アドホック署名を含む）の読み込みを許す広い例外です。付けると、アプリの中のライブラリを書き換えられた場合に、それが読み込まれるのを OS が防がなくなります。公証には付けたままでも出せますが、Apple はこの例外を必要なときだけ使うよう説明しています。必要だという根拠がない限り、このリポジトリでは付けず、自動で付けることもしません。
- LGPL の「利用者がライブラリを差し替えられること」の扱い（差し替え後に利用者自身が再署名する手順を案内する、この例外を付ける など）は、この entitlement の有無だけで満たせるとは限りません。正確な条件は LGPL の本文で確認し、決めてから実際の証明書で動作を確認してください。

- MP3 の基本特許は期限が切れていると一般に説明されていますが、配布する地域での扱いは各自で確認してください。

## 既知の制約・未対応

- アドホック署名のため、他の Mac では初回に「プライバシーとセキュリティ」での許可が必要です（上記「インストール」参照）。そのまま開けるようにするには Developer ID 署名と公証が必要です。
- 動作確認は macOS 27.0.1 / Apple M5 / ダークモードの 1 台だけです。アクセシビリティのラベルは Accessibility API で確認しましたが、VoiceOver での読み上げは試していません。
- 認識・変換の検証には、`say` で作った合成音声とそれを ffmpeg で動画にしたものを使いました。実際の録音・撮影データや複数話者での精度は確認していません。
- ウィンドウ上端のタイトルバー（ツールバー部分）へのドロップは受け付けません（macOS が管理する領域のため）。それ以外のウィンドウ内の領域はドロップを受け付けます。
- 表示言語の切り替え中に作成された一部の詳細メッセージ（ダウンロード失敗の詳細など）は、作成時の言語のまま残ることがあります。
- ReazonSpeech は文の間の無音で区切って認識するため、間を置かずに話し続ける音声では、10 秒ごとに最も静かな位置で区切ります（語の途中で切れることがあります）。出力に句読点は付きません。
- Apple の言語データの取得は macOS が行うため、進み方は OS 次第です（開発中、日本語の取得が 0% のまましばらく進まず、後でいつの間にか完了していたことがありました）。
- 翻訳、単語単位のタイムスタンプには対応していません。統合保存はテキスト形式のみです。
- 話者識別は合成音声（`say` の 2 つの声が交互に話す 39 秒の音声）でだけ確認しました。実際の会議の録音、声が似ている人、同時に話している部分での精度は確認していません。ライブ文字起こしの話者識別・編集には対応していません。
- Apple Intelligence による処理は、この Mac（Apple Intelligence が有効）でだけ確認しました。対応していない Mac では、ローカルの言語モデルか簡易抽出（AI なし）を使います。AI の結果には誤りが含まれることがあります。
- ローカルの言語モデルは、合成した短い文で読み込みと生成を確かめただけです。実際の録音・長い文字起こしでの精度、長時間の連続処理での発熱・速度は確かめていません。誤認識の修正は、検査を通っても意味の違う直し方をすることがありました（上記「この Mac での確認」）。
- 日本語の漢字だけの人名・地名は自動では判定できません（敬称の前の語・カタカナ・英語の固有名詞は守ります）。AI には変えないよう指示していますが、検査で止められない場合があります。
- Sona Air は Bundle ID が別なので、Vantage（とこれまでの Sona・Whisper Batch）の設定と取得済みのモデルは引き継ぎません。Air では Whisper などのモデルを取得し直す必要があります。
- 通知は .app として起動したときだけ使えます（開発時の実行ファイルでは使えません）。通知の許可の確認と実際の表示は、この環境では試していません。
- ライブ文字起こしで、選んだウィンドウだけの音声を取り込むことはできません（macOS はウィンドウを持つアプリ全体の音声を渡します）。ライブ文字起こしは Whisper だけに対応し、ファイルの一括処理と同時には使えません。
